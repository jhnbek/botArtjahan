## Вывод

По уточнению владельца, `botArtjahan` — рабочий проект разработки торгового робота, а `botArtjahan-main` — база знаний, из которой нужно брать информацию для его построения. Такое разделение намеренное и не является дефектом.

Ядро и опубликованный набор внутри `botArtjahan/knowledge` прошли тесты и полную проверку целостности. Эти результаты не следует автоматически переносить на данные в `botArtjahan-main/knowledge`: полный набор файлов второй папки отдельно не проверялся. Desktop-приложение рабочего проекта в текущей комплектации не запускается. Его код также содержит ошибку синхронизации инструмента и цены в форме paper/shadow-симуляции. Готовность торгового исполнения подтвердить невозможно: модуль broker_adapter отсутствует. Интеграция робота с базой знаний из `botArtjahan-main` пока не подтверждена.

## Область проверки

- `botArtjahan`: рабочий проект робота; Git-репозиторий с `knowledge_core`, шестью тестовыми модулями, опубликованной базой и тремя отслеживаемыми файлами `knowledge_bot` — README и двумя Python-модулями.
- `botArtjahan-main`: база знаний для разработки робота. Файлы непосредственно в `knowledge_core` побайтово совпадают с ядром рабочего проекта. Отсутствие `knowledge_bot` здесь соответствует назначению папки. Полная сверка двух наборов blobs не выполнялась.
- Проверены импорт, поиск, прослеживание источников, валидация, перенос базы, генерация каталога, CLI, CI и доступный desktop-код.
- Рабочее дерево `botArtjahan` перед аудитом было чистым. Для чтения Git использован разовый `safe.directory`, глобальная конфигурация не менялась.

## Проблемы

### 1. P1 — приложение не запускается из имеющихся исходников

Места: `botArtjahan/knowledge_bot/desktop_app.py:34–39`, `botArtjahan/knowledge_bot/chart_review_packet.py:20–27`.

`desktop_app.py` импортирует отсутствующие `binance_feed`, `bybit_feed`, `broker_adapter`, `casebook_store`, `build_level_feedback_statistics`. У `chart_review_packet.py` отсутствуют собственные локальные зависимости, включая `entry_context`, `level_discovery`, `runtime_root` и другие. Установка PySide6 сама по себе проблему не устранит.

Воспроизведение из корня workspace:

```powershell
python -B botArtjahan/knowledge_bot/desktop_app.py --help
```

Результат: `ModuleNotFoundError: No module named 'binance_feed'`.

Исправление: восстановить полный согласованный набор исходников робота и описание зависимостей, затем проверить импорт и запуск. Обновить документацию рабочего проекта: его корневой README говорит об отсутствии старого бота, тогда как назначение папки — разработка робота, а README внутри `knowledge_bot` предлагает запуск отсутствующих компонентов.

### 2. P2 — новый инструмент получает цену старого графика

Место: `botArtjahan/knowledge_bot/desktop_app.py:1159–1166`.

`_on_sync_execution_from_chart` берёт symbol из текущего значения комбобокса, а price — из `_last_close` ранее загруженного графика. Достаточно загрузить BTCUSDT, выбрать ETHUSDT без загрузки нового графика и нажать синхронизацию формы исполнения. Аналогичное рассогласование возможно при смене выбора во время фоновой загрузки.

В изолированном выполнении исходного метода с подставными полями формы получено:

```text
active_chart: ('binance', 'BTCUSDT', '1h')
execution_symbol: ETHUSDT
execution_price: 60000.0
```

Это искажает расчёты размера заявки и результаты симуляции. Реальная отправка ордеров не проверялась; доступное окно заявляет только paper/shadow.

Исправление: брать инструмент и цену из одного результата загруженного графика, например через `_active_chart_key` и соответствующую ему цену. До успешной загрузки запретить синхронизацию. Добавить тест смены выбора без новой загрузки и во время загрузки.

### 3. P2 — CI не проверяет присутствующее приложение

Место: `botArtjahan/.github/workflows/ci.yml:35–42`.

CI компилирует только `knowledge_core tests` и запускает только `test_knowledge_core_*.py`. Файлы `knowledge_bot` отслеживаются Git, но их импорты и запуск не проверяются. Поэтому зелёные проверки совместимы с блокирующей ошибкой из пункта 1.

Исправление: включить в CI рабочего проекта проверку импортов и безопасный smoke-тест приложения. Проверки ядра оставить отдельной частью: их успешность не подтверждает работоспособность робота и его интеграции с базой знаний.

### 4. P2 — сбой пересчёта статистики обратной связи скрывается

Место: `botArtjahan/knowledge_bot/desktop_app.py:935–946`.

После добавления события в JSONL вызывается `build_level_feedback_statistics()`. Любое исключение подавляется через `except Exception: pass`. Пользователь получает сообщение об успешном добавлении/удалении уровня, хотя статистический профиль может остаться устаревшим. README обещает пересборку профиля после каждой записи.

Вывод основан на коде; полный GUI-сценарий недоступен из-за пункта 1.

Исправление: сохранить уже записанное событие, но отдельно сообщить об ошибке обновления статистики, записать диагностическое сообщение и предоставить повторный пересчёт.
