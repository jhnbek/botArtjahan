# Наполненная база знаний

**[Читать каталог лекций и знаний](catalog/README.md)**

Здесь хранится полный опубликованный снимок: 68 лекций, 18 101 сегмент
транскриптов, 10 933 кадра, 7 462 записи OCR, 2 186 утверждений,
2 476 кандидатов, 27 правил и 15 понятий. Это сохранённые результаты извлечения;
исходные видео не входят в набор и не нужны для его использования.

| Путь | Назначение |
| --- | --- |
| `catalog/` | Тексты, карточки знаний, цитаты, условия и ссылки для чтения на GitHub |
| `knowledge.sqlite.gz` | Полная SQLite-база в сжатии gzip без потери данных |
| `blobs/` | Все зарегистрированные файлы: кадры, транскрипты, OCR и структурированные материалы |
| `manifest.json` | SHA-256 и размер распакованной SQLite и каждого файла |
| `packed-manifest.json` | Формат упаковки, SHA-256 и размер сжатой SQLite |

Имена файлов в `blobs/` соответствуют SHA-256 их содержимого. Названия,
типы, принадлежность к лекциям и связи записаны в SQLite. Каталог является
производным представлением: полные записи и история связей находятся в базе.

## Восстановление

Из корня клонированного репозитория или распакованного ZIP выполните:

```powershell
python -m knowledge_core restore-published knowledge ../lecture-knowledge
python -m knowledge_core validate ../lecture-knowledge
python -m knowledge_core search ../lecture-knowledge "уровень" --limit 10
```

Нужен Python 3.12 с SQLite FTS5. Результат — обычная `knowledge.sqlite`,
каталог `blobs/` и манифест в новом каталоге вне Git. Восстановление проверяет
хеши сжатого файла и распакованной базы, полный набор файлов и связи SQLite.
Для переноса восстановленной базы используйте вместе SQLite и `blobs/`.

SQLite сжата, чтобы уложиться в
[ограничение размера отдельного файла GitHub](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).
Материалы хранятся непосредственно в Git; Git LFS и внешнее хранилище
для скачивания этого снимка не требуются.

## Публичная редакция и достоверность

Личные пути компьютера в служебных полях заменены переносимыми ссылками.
`source-media/` обозначает исходный видеоматериал без его локального пути;
`legacy-reference/` обозначает старые файлы, отсутствующие в опубликованном
наборе. Исходные решения проверяющих сохранены, а личные ссылки на переписку
в описании происхождения заменены нейтральным пояснением.

Тексты, OCR, цитаты, условия, исключения и содержательные записи не переписаны.
Служебные идентификаторы и контрольные суммы построены заново для этой редакции.
Статус `imported_unverified` сохранён: публикация и техническая проверка
целостности не означают содержательного подтверждения всех утверждений.
