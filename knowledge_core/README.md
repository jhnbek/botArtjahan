# Ядро базы знаний

`knowledge_core` хранит извлечённые материалы лекций, утверждения, правила и их
происхождение независимо от бота. Для работы нужны Python 3.12 и SQLite с FTS5
(в стандартной Windows-сборке Python он доступен). Сторонние пакеты, сеть,
API-ключи и исходные видео не требуются.

Готовый публичный набор уже находится в [knowledge/](../knowledge/README.md).
Для его использования начните с команды `restore-published` ниже; повторное
извлечение материалов и исходный каталог лекций не нужны.

## Данные и происхождение

| Слой | Содержание |
| --- | --- |
| Источники | Точные байты транскриптов, сохранённых кадров, OCR и входных справочников; SHA-256 каждого файла |
| Фрагменты | Текст, время, лекция, исходный сегмент и связи с кадрами и OCR |
| Знания | Раздельные утверждения, кандидаты, правила и понятия; текст, цитата, интерпретация, условия и исключения |
| Проверки | Исходное решение, его область, автор и дата, если они действительно записаны |
| Версии | Состав каждого импорта; постоянные идентификаторы сущностей; отдельные редакции и связи |
| Поиск | Перестраиваемый индекс текста, OCR, знаний и терминов понятий |

Полная исходная запись сохраняется рядом с нормализованными полями. Старые
статусы и унаследованные условия сохраняются буквально. Перенос присваивает
`imported_unverified`: прежняя отметка о подписании остаётся отдельным событием
и не подтверждает достоверность утверждения. Неизвестные автор и дата равны
`NULL`. Решения с неразрешённой ссылкой сохраняются с предупреждением.

Логический идентификатор лекции берётся из `lecture_uid` или сохранённого поля
происхождения `source_video`. Последнее используется только как строка:
видеофайл не проверяется и не открывается. Перенос всего каталога проекта не
меняет идентификатор; редактирование самого ключа происхождения создаёт другую
лекцию. Порядок курса не служит идентификатором.

Изменение входного снимка создаёт отдельные редакции знаний. Связи источников и
события проверки принадлежат конкретному импорту. `--previous` переносит историю
в новый каталог; ранее созданная база остаётся самостоятельной.

## Импорт

Команды выполняются из каталога с пакетом `knowledge_core`. Пример путей:

```powershell
$sourceRoot = 'D:\data\retained-lectures'
$knowledgeRoot = 'D:\private-knowledge\snapshot-001'
python -m knowledge_core import --source $sourceRoot --destination $knowledgeRoot
python -m knowledge_core validate $knowledgeRoot
```

Каталог назначения должен находиться вне исходного проекта и любых Git-репозиториев.
Он содержит `knowledge.sqlite`, файлы `blobs/` с адресацией по хешу и локальные
отчёты проверки. Импорт сам не публикует данные. Для переноса базы нужны и
SQLite, и `blobs/`; публикация требует отдельной проверки состава материалов.
Включённый в репозиторий набор описан в [knowledge/README.md](../knowledge/README.md).

Адаптер читает только явный перечень в [sources.py](sources.py) и
[legacy_knowledge.py](legacy_knowledge.py): сохранённый корпус,
`source_multimodal_units.jsonl`, `claims_multimodal.jsonl`, канонический пул,
карточки правил, их происхождение, реестры решений и опциональный справочник
`knowledge_bot/knowledge_taxonomy.json`. Старый исполняемый код не импортируется.
Чаты, промпты, произвольные отчёты, рыночные данные и видео в перечень не входят.
Отсутствующий обязательный файл, отсутствующее или некорректное обязательное
поле прерывает импорт. Неизвестные дополнительные поля сохраняются.

Проверка перед принятием снимка сверяет перечень и хеши входов, число записей,
связи, схему, принадлежность версий, поисковый индекс и сохранённые байты.
Сначала строится временный каталог; готовое имя он получает только после
успешной проверки. Существующий каталог не заменяется. Повтор одинакового
импорта в ту же базу выполняет проверку без записи.

После изменения исходных извлечённых материалов:

```powershell
python -m knowledge_core import --source $sourceRoot `
  --previous $knowledgeRoot --destination 'D:\private-knowledge\snapshot-002'
```

Промежуточные каталоги неудачного импорта сохраняются рядом с назначением для
локальной диагностики. Они не являются принятыми снимками.

## Поиск и проверка источников

```powershell
python -m knowledge_core search $knowledgeRoot 'уровень' --limit 10
python -m knowledge_core show $knowledgeRoot '<target_id из результата поиска>'
```

Поиск требует совпадения всех слов запроса. По умолчанию ищет начала слов;
`--exact` включает совпадение целых слов. Индекс не выполняет смысловой поиск и
не генерирует ответы. `show` возвращает полный сохранённый текст, условия,
объявленные связи, происхождение, время и пути к кадрам. Результат содержит
все достижимые исходящие связи знаний, включая поддерживающие кандидаты правил.
Связи между свидетельствами обходятся в обе стороны: так результат OCR ведёт
к кадру и связанному тексту. Исходные направления и роли связей сохраняются.
Одноимённые старые идентификаторы различаются через `--namespace`.
`show --run-id <идентификатор импорта>` позволяет проверить предыдущую версию.

## Резервная копия и восстановление

```powershell
python -m knowledge_core export $knowledgeRoot 'D:\private-backups\knowledge-001'
python -m knowledge_core restore 'D:\private-backups\knowledge-001' `
  'D:\private-knowledge\restored-001'
```

Экспорт использует согласованный снимок SQLite и только зарегистрированные
файлы. Манифест содержит относительные пути, размеры и SHA-256. Восстановление
проверяет манифест, каждый файл и базу до принятия нового каталога. Резервная
копия на том же диске проверяет переносимость, но не защищает от отказа диска.

Опубликованный каталог с `knowledge.sqlite.gz`, `blobs/`, исходным
`manifest.json` и `packed-manifest.json` восстанавливается отдельной командой:

```powershell
python -m knowledge_core restore-published knowledge 'D:\private-knowledge\published-001'
python -m knowledge_core validate 'D:\private-knowledge\published-001'
```

Исходный каталог лекций не нужен. Команда проверяет оба манифеста, размеры и
SHA-256 сжатой и распакованной базы, её схему и точный перечень blobs. Только
SQLite распаковывается во временный каталог вне Git; зарегистрированные файлы
копируются и проверяются штатным экспортом. Назначение должно быть новым
каталогом вне Git. Временная база удаляется и при ошибке.

`packed-manifest.json` имеет формат `knowledge-core-published`,
`format_version: 1`, `schema_version: "1"` и объект `database` с полями
`path: "knowledge.sqlite.gz"`, `sha256` и `byte_size`. В обычном
`manifest.json` остаются хеш и размер несжатого `knowledge.sqlite` и всех blobs.
Повторные и неизвестные ключи, подмена пути и превышение заявленного размера
распакованной базы отклоняются.

## Проверки и границы

```powershell
python -m unittest discover -s tests -p 'test_knowledge_core_*.py' -v
python -m compileall -q knowledge_core
```

Тесты создают только синтетические данные во временных каталогах. Они проверяют
сохранность источников, историю изменённого текста и OCR, неоднозначные ссылки,
поиск, повреждение данных, ограничения путей и полный экспорт с восстановлением.

Технически корректный перенос не заменяет содержательную проверку: исправление
распознавания, оценка полноты объяснений, разбор противоречий и утверждение
понятий требуют отдельной работы с сохранёнными материалами. Автоматическая
правка исходного текста и повышение статуса достоверности здесь не выполняются.
