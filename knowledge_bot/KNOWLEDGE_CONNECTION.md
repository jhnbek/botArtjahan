# База знаний робота

`botArtjahan` — торговый робот, уже построенный на основе базы знаний.
`botArtjahan-main/knowledge` — справочная база для ручного обучения робота:
разбора ошибок, проверки правил и корректировки его кода и настроек человеком.
Самообучение модели не требуется и не входит в назначение подключения.

Источник знаний по умолчанию — `../botArtjahan-main/knowledge`.
Модуль `knowledge_bot.knowledge_base` работает
самостоятельно на стандартной библиотеке Python и не требует биржевых модулей.

## Подключение и поиск

Из каталога `botArtjahan`:

```powershell
python -m knowledge_bot.knowledge_base connect
python -m knowledge_bot.knowledge_base status
python -m knowledge_bot.knowledge_base search "уровень" --limit 5
python -m knowledge_bot.knowledge_base context "ложный пробой" --limit 5
python -m knowledge_bot.knowledge_base show "<target_id из поиска>"
```

`connect` проверяет манифесты, контрольные суммы, схему, связи, поисковый индекс
и все файлы. Затем он создаёт независимый снимок в `../.bot_knowledge` и атомарно
переключает указатель `active.json`. Исходная база не изменяется. При ошибке
обновления остаётся доступен предыдущий снимок. Подключение большого набора
занимает несколько минут; текущий набор требует около 1,3 ГБ на каждый снимок.
Предыдущие снимки сохраняются; автоматического удаления нет.

После подключения запросы работают локально, без повторной распаковки и сети.
`validate` повторно проверяет активный снимок. `status` показывает результат
проверки на момент подключения, а не запускает новую проверку.

Пути можно переопределить через `BOT_KNOWLEDGE_SOURCE` и `BOT_KNOWLEDGE_CACHE`
или глобальные CLI-флаги `--source` и `--cache` перед именем команды. Один cache
обслуживает один выбранный источник; после изменения источника нужен `connect`.
Cache должен находиться вне Git и отдельно от каталога исходной публикации.

## Использование из кода робота

```python
from knowledge_bot.knowledge_base import KnowledgeBase

knowledge = KnowledgeBase()
context = knowledge.context("ложный пробой", limit=5)
for hit in context["results"]:
    original = knowledge.show(hit["target_id"])
    # original содержит полный текст, условия, цитаты, события проверки,
    # связанные свидетельства и локальные пути к файлам источников.
```

Поиск использует FTS: все слова запроса должны совпасть, по умолчанию допускаются
разные окончания слов. Это поиск материалов, а не генерация ответа моделью.
Для согласованности при параллельном обновлении можно вызвать
`knowledge_core.query.trace(context["dataset"], target_id)` на том же снимке.

В `build_live_kb_chart_review_packet` добавлено поле `knowledge_references`.
Запрос задаётся через `args.knowledge_query`; без него используется «уровень»
как общий справочный запрос. Desktop-код отображает найденные выдержки и ID
источников. При недоступности подключения пакет содержит явную ошибку.
Модули desktop-приложения восстановлены из локальной истории Git. Запуск окна:

```powershell
.\.venv\Scripts\python.exe knowledge_bot/desktop_app.py
```

## Ручной разбор и исправление ошибок

Подтверждённые вручную изломы с полной датой `human_bsu_date` теперь используются
при построении разметки. Для текущих биржи, инструмента и таймфрейма алгоритм
находит свечу точно по дате UTC и выбирает ближайший к ручной цене high/low
(расхождение допускается до 0,1%). Отсутствующая дата или несоответствие цены
не подменяются ближайшей свечой. Линия подписана «БСУ подтверждён вами» и имеет
источник `human_confirmed_inflection`. Удаление ручного уровня убирает и это
основание при следующем расчёте. Ошибочные или отозванные метки не используются.
Сверка качества продолжает оценивать автоматические находки отдельно от таких
ручных оснований, чтобы не выдавать их за улучшение автоматической точности.

В окне робота сразу доступна кнопка **«Показать уровень излома тренда»**.
Выберите биржу, инструмент и таймфрейм и нажмите её: свечи загрузятся и на
графике появятся кандидаты излома. Предварительный общий анализ не нужен.
Повторное нажатие обновляет график. Кнопка «Загрузить и проанализировать» также
использует этот же режим. Дополнительно сохраняются подтверждённые лимитные
уровни, уступившие более сильному излому (пример 59 081): они подписаны
«Лимитный · второстепенный» и не входят в число изломов. Остальные типы
автоматических уровней в этом режиме не показываются.
Круг отмечает бар-основание; подпись показывает цену и статус проверки.
Для исторической проверки выводятся также далёкие и отклонённые кандидаты,
поэтому появление линии не означает разрешение сделки.

Рядом доступны два независимых режима:

- **«Показать зеркальные и лимитные уровни»** — только автоматические уровни
  с признаками `mirror_level`, `limit_level` или `two_bar_limit`. Кружки
  отмечают БСУ и все касания high/low в пределах допуска 0,06 ATR расчёта,
  включая соседние свечи. Дополнительно сохраняются явные лимитные и зеркальные
  подтверждения детектора с их собственными допусками. Пересечение линии телом
  свечи само по себе не добавляет кружок касания.
- **«Показать уровни, образованные паранормальным баром»** — только автоматические
  уровни с признаком `paranormal_bar`. Кружок отмечает high/low исходного БСУ,
  по которому детектор установил этот признак.

Кружки расположены на фактических экстремумах свечей, поэтому при недоходе
или усреднении линии могут немного отстоять от неё. При наведении показываются
роль бара, дата UTC и цена. Оба режима работают без предварительного общего
анализа, загружают выбранный инструмент и таймфрейм и заменяют предыдущий набор
линий. Ручные линии в этих двух режимах скрыты, ручное редактирование доступно
после возвращения к изломам; сохранённые отметки не удаляются.

Новые удаления и возвраты роботских линий привязаны к выбранному режиму.
Отклонённый излом может отображаться как зеркальный/лимитный либо паранормальный
уровень. Старые удаления с признаком `inflection` относятся к режиму изломов;
старые записи без определения типа сохраняют общий смысл удаления.

По уточнению пользователя от 22.09.2026 граница БСУ — его high/low, а не close.
High/low кандидата должен выйти за диапазон предыдущих 20 баров; закрытие
самого БСУ за этим диапазоном не требуется. Движение от начального закрытия
подхода до high/low БСУ должно составить не менее 2,5 ATR; эффективность
подхода по закрытиям — не ниже 0,55. Последующие бары могут закрываться выше
close верхнего БСУ или ниже close нижнего БСУ, но не за его high/low.
Прокол хвостом с закрытием обратно не переносит БСУ на следующий бар в ходе
подтверждения одного разворота. Обратный ход подтверждается закрытием
на расстоянии не менее 2,5 ATR от high/low БСУ в следующие 20 баров,
не раньше третьего последующего бара; закрытие за экстремумом
БСУ до подтверждения отменяет кандидата. Линия проводится по high/low выбранного
БСУ, без усреднения с соседними экстремумами. Параметры — проверяемая реализация,
а не дословные правила базы. Разметка использует последующие бары; дата
подтверждения сохраняется в `inflection_check`.

Для излома с историческим зеркальным подтверждением порог эффективности
подхода 0,55 не является обязательным. Подтверждение требует касания с
противоположной стороны ранее последних 20 баров, совпадения цен в пределах
0,04 ATR БСУ и последующего закрытия через уровень с запасом 0,25 ATR.
Требования движения и разворота от 2,5 ATR и удержания хвоста сохраняются.
Дата, цена зеркального касания и применение исключения сохраняются в
`inflection_check`. Допуски — параметры реализации для дальнейшей ручной проверки.

После разбора боковиков от 22.09.2026 добавлен фильтр более широкого контекста:
high/low БСУ должен выйти за диапазон предыдущих 60 баров с запасом 0,06 ATR
БСУ. При короткой истории используется доступная часть окна; минимум истории
по-прежнему определяется исходным поиском кандидатов. Это фильтр локальных
волн и откатов, а не точное восстановление нарисованных пользователем каналов.
Запас не позволяет незначительному новому экстремуму после сдвига окна вернуть
почти тот же отвергнутый откат как другой БСУ.

Исключение допускается для исторической границы, уже подтверждённой с двух
сторон. Сначала должен существовать экстремум предыдущих 20 баров с разворотом
закрытиями от 2,5 ATR, затем — касание с противоположной стороны после его
подтверждения, также с отходом от 2,5 ATR. Касания совпадают с текущей ценой
в пределах 0,06 ATR текущего БСУ. Используется ATR соответствующего старого
бара для его реакции, только уже известные свечи и касания старше 20 баров.
Проколы хвостами допустимы, закрытие за хвостом до реакции отменяет подтверждение.
Пример — 74 900: 16 марта и 29 апреля. Единственного зеркального касания
недостаточно для обхода фильтра широкого контекста.

Соседний более глубокий разворот может понизить предыдущий излом до
второстепенного уровня: новый БСУ того же направления находится не дальше
40 баров и 1 ATR старого БСУ; между ними нет другого подтверждённого
структурного разворота противоположного направления. Требуются подтверждение
нового излома и закрытие за хвостом старого. Смена статуса происходит только
когда известны оба условия (`superseded_by.effective_time`). Повторный подход
к старому хвосту с допуском 0,06 ATR и закрытием с удержанием сохраняется
как `limit_level`. Для 59 081 это касание 24 июня; закрытие за хвостом — 30 июня,
а новый излом 58 042 подтверждается алгоритмом 5 июля. До этой даты смена
статуса не применяется. Недоход 30 июня подтверждает 58 042 без переноса БСУ.

Если несколько независимо подтверждённых БСУ попали в один ценовой кластер,
для линии берётся последний действующий БСУ с его точной ценой. Это сохраняет
усиление уровня новым баром, в частности 14 января на 97 963,2. Ручное подтверждение
совпадающего БСУ сохраняет найденные автоматически подтверждения и их даты.
Цены и даты примеров не используются как условия в коде; параметры метода —
проверяемые гипотезы. Проверка на размеченном наборе не является оценкой точности
на независимых рынках. Самообучение отсутствует.

Чтобы исправить уровень, нажмите «Удалить уровень робота», выберите линию и
укажите причину. Затем через «Добавить свой уровень» укажите правильную цену
и пояснение. Удалённую линию можно вернуть кнопкой «Вернуть последний уровень».
Для удаления сохраняются также признаки излома и БСУ. Исправления записываются
в локальный журнал ручной проверки и не переписывают стратегию автоматически.

1. Зафиксировать ошибку робота: инструмент, время, рыночную ситуацию,
   фактическое решение и ожидаемое поведение.
2. Найти относящиеся к ситуации материалы через `search` или `context`.
3. Открыть первоисточники через `show`, проверить условия и исключения правила.
4. На основании разбора вручную скорректировать код или настройки в `botArtjahan`.
5. Проверить исправление на исходном примере и добавить подходящую проверку,
   чтобы ошибка не повторилась. Сохранить ID источников в описании исправления.

Поиск предоставляет справочные материалы. Изменение логики робота остаётся
отдельным осознанным действием пользователя или разработчика. Исправление кода
робота не требует переподключения неизменившейся базы.

## Обновление справочной базы

Последний подробный ручной разбор: [боковики и подтверждения от 22.09.2026](../_knowledge_base/manual_reviews/channel_review_20260922/README.md).
В нём сохранены все 10 пояснений пользователя, точные БСУ и цены из журнала,
снимки свечей и исходная проверка автоматического расчёта. `review.json`
разделяет полезность уровня, его тип и силу: оставленный 59 081 не является
положительным примером окончательного излома после 30 июня, а отклонение
излома около 111 950 не запрещает зеркальный и лимитный уровень в этой области.
На основании этого разбора изменён `level_discovery.py`; результаты после
изменения сохранены в [проверке новой методики](../_knowledge_base/manual_reviews/inflection_context_v3_20260922/README.md).
Сам файл разметки не загружается как список запрещённых цен. Автоматические
регрессионные проверки находятся в `tests/test_inflection_detection.py`.

Чтобы робот видел новые материалы, нужно добавить их в базу знаний и подготовить
обновлённую публикацию `botArtjahan-main/knowledge` с согласованными манифестами,
SQLite и blobs. После этого повторить `connect`. До успешного обновления робот
использует предыдущую проверенную версию.

Статусы проверки знаний сохраняются; `imported_unverified` не становится
одобренным правилом. При ручном разборе нужно сверять материал с первоисточником.
Получение справочного контекста не меняет разрешения на торговые операции.

Проверки:

```powershell
python -m unittest discover -s tests -p "test_knowledge*.py" -v
```
